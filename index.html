Why Edwards curves for zero‑knowledge?
One addition formula that handles every case, including doubling — and why that matters inside a circuit.
NOV 2026 · curves

The problem with Weierstrass

The standard form y² = x³ + ax + b has incomplete addition formulas: separate logic for doubling, for adding distinct points, and for the point at infinity. In a circuit every branch costs constraints.

Edwards curves fix this

An Edwards curve is defined as

x² + y² = 1 + d·x²y²

and its addition law is complete; one formula covers every case, doubling included:

(x₁, y₁) + (x₂, y₂) = ( (x₁y₂ + y₁x₂) / (1 + d·x₁x₂y₁y₂), (y₁y₂ − x₁x₂) / (1 − d·x₁x₂y₁y₂) )

Why it matters

  • No edge cases, so no branching, so constant‑time operations and side‑channel resistance.
  • Every Edwards curve is birationally equivalent to a Weierstrass curve; nothing is lost in the translation.
  • The twisted form ax² + y² = 1 + dx²y² generalises further.

In production

ed25519 for signatures, Jubjub in Zcash, Baby Jubjub in Ethereum circuits — all chosen for complete addition laws and efficiency inside arithmetic circuits.

Bulletproofs and the inner product argument
Short proofs, no trusted setup. Each round halves the vector, so the proof is logarithmic in size.
NOV 2026 · proofs

Pedersen commitments

The building block. A commitment to value v with blinding factor r:

C = v·G + r·H

where G and H are generator points. Computationally binding, perfectly hiding, and additively homomorphic:

C(v₁) + C(v₂) = C(v₁ + v₂)

The inner product argument

The IPA proves knowledge of vectors a, b with ⟨a, b⟩ = c. Each round halves the vectors, so a proof over n elements takes O(log n) rounds.

Range proofs

Proving v ∈ [0, 2ⁿ) without revealing v: decompose in binary, express as an arithmetic circuit, reduce to an inner product relation, apply the IPA. About 672 bytes for a 64‑bit range.

Against SNARKs

No trusted setup, no toxic waste, no ceremony. The cost is O(n) verification instead of O(1). For many applications the simpler trust model wins.

Pedersen commitments in arkworks
A minimal Rust example on BLS12‑381, and the homomorphic property in one line.
NOV 2026 · rust

The ecosystem

arkworks is the standard Rust library family for zero‑knowledge work: curve arithmetic, finite fields, R1CS constraint systems and proof systems.

Minimal Pedersen on BLS12‑381

use ark_bls12_381::G1Projective as G;
use ark_ec::Group;
use ark_std::UniformRand;

fn pedersen_commit(v: u64, r: ark_bls12_381::Fr, g: G, h: G) -> G {
    // C = v*G + r*H
    g.mul_bigint(&[v]) + h * r
}

fn main() {
    let mut rng = ark_std::test_rng();
    let g = G::generator();
    let h = G::rand(&mut rng);
    let r = ark_bls12_381::Fr::rand(&mut rng);

    let c1 = pedersen_commit(5, r, g, h);
    let c2 = pedersen_commit(3, r, g, h);
    // homomorphic: c1 + c2 commits to 8
}

Why BLS12‑381

A 255‑bit scalar field gives 128‑bit security, pairings are efficient, and it's what Ethereum, Zcash and Filecoin already use.

The homomorphic property

Because commitments add, you can compute on committed values without opening them: C(v₁) + C(v₂) = C(v₁ + v₂). This is the foundation of confidential transactions.
